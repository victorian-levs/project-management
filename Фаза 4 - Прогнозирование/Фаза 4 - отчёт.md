## 4. Модель 1: по числу задач

**Как работает:** в каждом запуске «проживаем» неделю за неделей. На каждой неделе случайно берём из истории одно из 9 значений «закрыто задач» и складываем, пока не наберётся 9 задач. Число недель записываем. Всего 10 000 запусков.

| Недель | Доля запусков | Накопленная доля |
|---|---|---|
| 2 | 51,8 % | 51,8 % |
| 3 | 30,6 % | 82,4 % |
| 4 | 12,5 % | 94,9 % |
| 5 | 3,8 % | 98,7 % |
| 6 и больше | 1,3 % | 100 % |

**С достоверностью 80 % фаза 5 займёт 3 недели.**

## 5. Модель 2: по человеко-часам

**Как работает:** в каждом запуске сначала случайно выбираем длительность каждой задачи из треугольного распределения по её трём оценкам и складываем — получаем, сколько всего часов нужно. Потом неделя за неделей случайно берём из истории «сколько часов команда потратила за неделю», пока не наберём нужное. Всего 10 000 запусков.

| Недель | Доля запусков | Накопленная доля |
|---|---|---|
| 1 | 3,7 % | 3,7 % |
| 2 | 29,9 % | 33,5 % |
| 3 | 33,6 % | 67,1 % |
| 4 | 20,8 % | 87,9 % |
| 5 | 8,8 % | 96,7 % |
| 6 и больше | 3,3 % | 100 % |

**С достоверностью 80 % фаза 5 займёт 4 недели.**

## 6. Сравнение

Вторая модель даёт на неделю больше: 4 недели против 3. Причины:

- **Модель 1 считает все задачи одинаковыми.** В истории много маленьких задач, например оценки экспертов по 1 часу, и в удачные недели закрывалось по 7 штук. Задачи фазы 5 в среднем крупнее (3,1 ч против 2,8 ч), и среди них есть большие: код эвристик — до 8 часов.
- **Модель 2 учитывает размер задач и риск.** Пессимистичные оценки длиннее ожидаемых, поэтому сумма часов чаще получается больше средней.
- **Часов в неделю бывает очень мало** (1 и 3 часа). Модель 2 сильнее «застревает» на таких неделях, чем модель 1 на неделе с нулём задач.

**Вывод:** планируем фазу 5 на **4 недели**, с 11.11 по 08.12, по более осторожной модели 2.

Код симуляции — «Расчёты/monte-carlo.mjs» (запуск: npm run phase4).
