# Фаза 3. Оценка проекта

**Состояние: не начата.** Выполняется для концепции, выбранной в фазе 1, после распределения работ в фазе 2.

## Требования задания

1. Набросать не менее 10 Use Cases с альтернативными и негативными сценариями.
2. Оценить проект в COSMIC Function Points.
3. Оценить проект в Use Case Points и прикинуть трудозатраты.
4. Оценить проект коллективным экспертным путём: трудозатраты каждого Use Case или более мелких элементов (User Story, Slices) любым экспертным методом с достижением согласия; агрегировать в оценку проекта.
5. Сделать выводы о масштабе, нужном размере команды и специфических требованиях к участникам, ориентировочном сроке, а также о функциях, от которых можно отказаться.

LLM разрешена для набрасывания Use Cases с контролем альтернативных и негативных сценариев.

## Ожидаемые результаты

- Каталог Use Cases (10–15) с основными, альтернативными и негативными потоками.
- Расчёт COSMIC с явно определённой границей и функциональными пользователями.
- Расчёт UCP: акторы, транзакции, технические и средовые факторы, трудозатраты.
- Протокол коллективной экспертной оценки и агрегированная оценка.
- Сравнение трёх оценок и выводы.

## Задел для MusicApp (если выбран)

Это заготовка для будущей работы, а не выполненная фаза.

- **Use Cases.** Отправная точка — UC-01…UC-14 из [документа фазы 1](<../Фаза 1 - Выбор концепции проекта/1. Альтернативы и критерии.md>). Сначала нужно подтвердить модель ролей: в коде загрузку делает пользователь-исполнитель, в MVP — администратор. Слишком широкие сценарии (например, UC-05, UC-14) пересматриваются при сохранении 10–15 содержательных целей. Нажатия кнопок, проверки прав, HTTP 401 и операции с БД отдельными Use Cases не становятся.
- **Негативные сценарии** включаются в соответствующие Use Cases и не увеличивают их число: неподдерживаемый или повреждённый файл, недоступное хранилище, нет прав на чужой плейлист, пустой поиск, трек удалён из каталога, прерывание воспроизведения, нет истории для подборки.
- **COSMIC.** Объект измерения — MusicApp как веб-система целиком: UI и backend внутри границы. Таблицы PostgreSQL не становятся внешними пользователями. MinIO не объявляется внешним актором только потому, что это отдельный сервис: при такой границе он часть системы. Функциональные пользователи — слушатель и администратор. Хранение и чтение данных учитываются как Write и Read по правилам метода, а не по числу HTTP-запросов или строк кода.
- **UCP.** Используется согласованный каталог сценариев, реальные акторы и транзакции основных и альтернативных потоков. Трудозатраты не получаются умножением числа названий Use Cases на коэффициент.
- **Возможные сокращения объёма:** персональная подборка, история прослушивания, подписки на исполнителей, публикация плейлистов по ссылке. Важность и «вес» оценивает команда. Прослушивание, каталог, базовая загрузка музыки и личные плейлисты сохраняют смысл продукта.
