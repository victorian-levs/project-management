## 2. Use Cases

Акторы: **слушатель** (до регистрации — посетитель) и **администратор** каталога. Use Cases набросаны с помощью LLM и проверены командой.

**UC-01. Зарегистрироваться** (посетитель)
- Основной: вводит имя, почту и пароль → система проверяет данные и создаёт учётную запись → открывается главная страница.
- Альтернативный: уже есть учётная запись → переход ко входу.
- Негативные: почта уже занята; пароль слишком простой.

**UC-02. Войти и выйти** (слушатель)
- Основной: вводит почту и пароль → система открывает сеанс. По кнопке «Выйти» сеанс закрывается.
- Негативные: неверный пароль (после 5 попыток пауза); сеанс истёк → снова вход.

**UC-03. Найти треки и исполнителей** (слушатель)
- Основной: вводит запрос → система ищет по названию трека и имени исполнителя → показывает два списка → слушатель открывает трек или исполнителя.
- Альтернативный: запрос короче 2 символов → показываются популярные треки.
- Негативный: ничего не найдено → сообщение и популярные треки.

**UC-04. Открыть страницу исполнителя** (слушатель)
- Основной: выбирает исполнителя → видит карточку, его треки и кнопку подписки.
- Негативный: исполнитель снят из каталога → «Исполнитель недоступен».

**UC-05. Прослушать трек и управлять очередью** (слушатель)
- Основной: выбирает трек → он и следующие треки списка встают в очередь → играет трек → пауза, перемотка, следующий и предыдущий → прослушивание записывается в историю.
- Альтернативные: добавить трек в конец очереди; убрать трек или поменять порядок; перемешать очередь.
- Негативные: трек снят с публикации → пропускается; файл недоступен → повтор, потом пропуск; пропала сеть → пауза и продолжение с того же места.

**UC-06. Вести избранное** (слушатель)
- Основной: нажимает «В избранное» у трека → трек сохраняется → в разделе «Избранное» можно запустить или убрать трек.
- Негативный: трек снят с публикации → показан серым, запустить нельзя.

**UC-07. Создать плейлист** (слушатель)
- Основной: «Новый плейлист» → вводит название → создаётся пустой личный плейлист.
- Альтернативный: создать плейлист сразу из трека.
- Негативный: пустое название → подставляется «Плейлист N».

**UC-08. Изменить или удалить плейлист** (владелец)
- Основной: открывает свой плейлист → добавляет треки, меняет порядок, переименовывает → изменения сохраняются.
- Альтернативные: удалить трек из плейлиста; удалить плейлист после подтверждения.
- Негативные: чужой плейлист можно только смотреть; трек уже есть в плейлисте → предупреждение.

**UC-09. Поделиться плейлистом по ссылке** (владелец и слушатель)
- Основной: владелец нажимает «Поделиться» → получает ссылку → другой слушатель открывает её и слушает плейлист.
- Альтернативные: владелец закрывает доступ, и ссылка перестаёт работать; гость без учётной записи → предложение войти.
- Негативный: ссылка неверная или закрыта → «Плейлист недоступен».

**UC-10. Подписаться на исполнителя** (слушатель)
- Основной: «Подписаться» на странице исполнителя → в разделе «Подписки» видны исполнители и их новые треки.
- Альтернативный: отписаться.
- Негативный: исполнитель снят из каталога → подписка скрывается.

**UC-11. Посмотреть историю прослушивания** (слушатель)
- Основной: открывает «Историю» → видит треки по датам → запускает трек снова.
- Альтернативный: очистить историю.
- Негативный: истории нет → подсказка начать слушать.

**UC-12. Запустить персональную подборку** (слушатель)
- Основной: «Моя подборка» → система собирает 30 треков по избранному, подпискам и популярности, без недавно прослушанных → подборка встаёт в очередь.
- Альтернативные: обновить подборку; убрать трек кнопкой «Не нравится».
- Негативные: новый пользователь без истории → подборка из популярного; в каталоге мало треков → короткая подборка.

**UC-13. Загрузить и опубликовать трек** (администратор)
- Основной: выбирает аудиофайл → вводит название, исполнителя, жанр → система проверяет формат и размер → сохраняет файл и трек → трек появляется в каталоге.
- Альтернативные: исполнителя нет в каталоге → создать карточку (UC-14); сохранить черновик без публикации.
- Негативные: формат не поддерживается или файл повреждён → отказ с причиной; хранилище недоступно → трек не создаётся; такой трек уже есть → предупреждение.

**UC-14. Обновить каталог** (администратор)
- Основной: находит трек или исполнителя → меняет данные (название, фото, описание) → изменения сохраняются.
- Альтернативные: снять трек с публикации (пропадает из поиска); вернуть трек; снять исполнителя целиком.
- Негативный: двое правят одно и то же одновременно → сообщение и перезагрузка данных.

## 4. Оценка в Use Case Points

**Акторы.** Слушатель и администратор работают через интерфейс, это сложные акторы по 3 балла. UAW = 6.

**Сценарии.** Сложность считается по числу транзакций: до 3 — простой (5 баллов), 4–7 — средний (10), больше 7 — сложный (15).

|---|---|---|---|

| | | **UUCW** | **130** |

**Поправочные факторы.** 13 технических факторов (распределённость, скорость потока, безопасность и другие) дали сумму 35, поэтому TCF = 0,6 + 0,01 × 35 = **0,95**. 8 факторов среды (опыт, мотивация, стабильность требований, частичная занятость) дали сумму 18,5, поэтому ECF = 1,4 − 0,03 × 18,5 = **0,845**.

**Расчёт:**

- UUCP = 6 + 130 = 136.
- UCP = 136 × 0,95 × 0,845 = **109,2**.
- Трудозатраты по норме Карнера (20 ч на UCP): 109,2 × 20 ≈ **2183 ч**.

## 5. Экспертная оценка

Каждый Use Case оценили в часах разработки целиком: интерфейс, сервер и тесты. Отдельно оценили **общие работы**: каркас приложения, дизайн, развёртывание и сквозные тесты.

**Метод — Дельфи в два тура.** Сначала каждый оценивает сам. Если разница больше 20 % от медианы, авторы крайних оценок объясняют свои допущения, затем второй тур. Итог — медиана второго тура. Во втором туре разница везде не больше 10 %, то есть команда согласовала оценку.

## 6. Сравнение и выводы

| Метод | Трудозатраты |
|---|---|
| COSMIC (101 CFP × 12 ч) | 1212 ч |
| Экспертная оценка | 1300 ч |
| UCP (109,2 × 20 ч) | 2183 ч |

**Почему UCP больше.** Норма 20 ч на UCP рассчитана на полный цикл с документацией и управлением проектом, и она грубо округляет сложность сценариев. COSMIC и экспертная оценка близки (разница 7 %), поэтому для планирования берём **экспертную оценку, 1300 ч**. Она ещё и разбита по сценариям.

**Масштаб.** Небольшой проект: 14 сценариев, около 100 CFP, около 1300 человеко-часов.

**Команда — 6 человек:**

- аналитик-дизайнер: требования, прототип интерфейса;
- 2 backend-разработчика: Java и Spring Boot, PostgreSQL, хранилище файлов MinIO, потоковая отдача аудио;
- 2 frontend-разработчика: React, аудиоплеер с очередью;
- тестировщик, в том числе нагрузочное тестирование воспроизведения.

**Срок.** 1300 ч / 6 человек / 40 ч в неделю ≈ 5,5 недели, если бы все работали без простоев. Задачи зависят друг от друга, поэтому реально **около 3 месяцев**. Точный план — в фазе 5.
