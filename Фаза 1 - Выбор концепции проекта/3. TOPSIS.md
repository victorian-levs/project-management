# 3. Нечёткий коллективный TOPSIS

> Расчёт выполнен по ответам трёх экспертов (`npm run phase1:calc`). Все промежуточные таблицы — в расчётной книге [Фаза 1 расчёты TOPSIS и МАИ.xlsx](<Расчёты/Фаза 1 расчёты TOPSIS и МАИ.xlsx>) (листы «Исходные TOPSIS» и «TOPSIS расчёт») и в [Результатах расчётов](<Расчёты/Результаты расчётов.md>).

## Исходные данные

Каждый из трёх экспертов независимо даёт 5 оценок важности критериев и 20 оценок альтернатив по шкале 1–9 (см. [шкалы](<1. Альтернативы и критерии.md#шкалы>)). Исходные ответы хранятся с авторством в `Данные/topsis_оценки.csv`.

## Формирование треугольных чисел

Задание требует упорядочить три оценки и рассматривать их как пессимистичную, ожидаемую и оптимистичную. Для каждой величины (важности критерия или оценки альтернативы по критерию):

- l — минимальная из трёх оценок (пессимистичная);
- m — средняя по порядку, то есть **медиана**, а не среднее арифметическое (ожидаемая);
- u — максимальная (оптимистичная).

Пример: оценки 3, 8, 5 дают (3; 5; 8).

**Критерий затрат K4.** Тройка трудоёмкости упорядочивается так же, по числу: l ≤ m ≤ u. Но для затрат благоприятный исход — **l**, наименьшая трудоёмкость, а неблагоприятный — u. Сортировка задаёт порядок чисел, а направление предпочтения учитывается отдельно, при нормировании. Формулы ниже переворачивают тройку так, что после нормирования она снова возрастает и «больше — лучше».

## Стадии расчёта

Используется вариант Chen (2000) с треугольными нечёткими числами.

1. **Нечёткие веса.** w_j = (l_j / 9; m_j / 9; u_j / 9), где (l_j; m_j; u_j) — тройка важности критерия j. Деление на максимум шкалы переводит веса в диапазон (0; 1].
2. **Нечёткая матрица.** x_ij = (l_ij; m_ij; u_ij) — тройка оценок альтернативы i по критерию j.
3. **Нормирование.**
   - Выгода (K1, K2, K3, K5): r_ij = (l_ij / u*_j; m_ij / u*_j; u_ij / u*_j), где u*_j = max_i u_ij.
   - Затраты (K4): r_ij = (l⁻_j / u_ij; l⁻_j / m_ij; l⁻_j / l_ij), где l⁻_j = min_i l_ij.
   - Деления на ноль нет: шкала начинается с 1, поэтому все l ≥ 1. Скрипт отклоняет оценки вне 1–9, дробные и пустые значения.
4. **Взвешенная матрица.** v_ij = r_ij ⊗ w_j — покомпонентное произведение троек.
5. **Идеальное и антиидеальное решения.** A+ = (1; 1; 1) и A− = (0; 0; 0) по каждому критерию: после нормирования и взвешивания все компоненты лежат в [0; 1].
6. **Расстояния.** Вершинное расстояние d(a, b) = √(((a₁ − b₁)² + (a₂ − b₂)² + (a₃ − b₃)²) / 3). Для альтернативы i: D+_i = Σ_j d(v_ij, A+), D−_i = Σ_j d(v_ij, A−).
7. **Коэффициент близости.** CC_i = D−_i / (D+_i + D−_i), CC ∈ [0; 1]. Альтернативы ранжируются по убыванию CC.

Нечёткий расчёт не заменяется чётким расчётом по средним.

## Проверки

- Вход: ровно три эксперта, все 75 значений заполнены, целые 1–9, без повторов.
- Ручной пример в тестах: при весе (1; 1; 1) оценки (9; 9; 9) и (3; 3; 3) дают CC = 1 и CC = 1/3.
- Инварианты: одинаковые оценки дают одинаковый CC; CC ∈ [0; 1]; для затрат нормированная тройка возрастает, а меньшая трудоёмкость даёт больший CC.
- Расчётная книга содержит все промежуточные таблицы в виде формул Excel. Скрипт вычисляет их и сравнивает итоговые CC и ранги со своим независимым расчётом; при расхождении больше 10⁻⁹ результаты не записываются.

MusicApp лидирует с заметным отрывом (0,663 против 0,567). Его тройки по K2 (8; 9; 9), K3 (8; 8; 9) и K5 (8; 9; 9) — лучшие среди альтернатив; единственная слабая сторона — трудоёмкость K4 (5; 6; 6), где лучше A4 (3; 4; 4). Второе и третье места близки (0,567 и 0,554), их порядок менее устойчив. Jarvis последний из-за низкой понятности области (3; 4; 5) и наибольшей трудоёмкости (8; 8; 9).
