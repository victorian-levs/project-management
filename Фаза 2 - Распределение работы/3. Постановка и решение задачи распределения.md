# 3. Постановка и решение задачи распределения

## Постановка

**Обозначения.** Участники i ∈ {E1, E2, E3}, задачи j ∈ {P3-02, …, P3-13}; c_j — сложность задачи в часах (медиана Дельфи); p_ij — предпочтение участника i для задачи j (1–5); C = Σ c_j = 46 ч.

**Переменные.** x_ij ∈ {0, 1}: x_ij = 1, если задача j назначена участнику i. Всего 36 булевых переменных.

**Целевая функция.**

max Σ_i Σ_j p_ij · c_j · x_ij

Каждый час работы взвешивается желанием исполнителя. Умножение на c_j важно: удовольствие от большой задачи должно весить больше, чем от маленькой. Иначе модель отдавала бы любимые мелкие задачи и равнодушно распределяла крупные.

**Ограничения.**

1. Каждая задача назначена ровно одному: Σ_i x_ij = 1 для всех j.
2. Баланс нагрузки ±15 % от среднего: 0,85 · C/3 ≤ Σ_j c_j · x_ij ≤ 1,15 · C/3, то есть от 13,03 до 17,63 ч. Без этого ограничения участник с широкими интересами получил бы непропорционально много работы.
3. Задачи одного метода выполняет один человек: x_i,P3-06 = x_i,P3-07 и x_i,P3-08 = x_i,P3-09. Модель измерения и подсчёт по ней должен делать тот, кто эту модель построил.
4. COSMIC и UCP считают разные люди: x_i,P3-06 + x_i,P3-08 ≤ 1. Так две оценки размера получаются независимыми, и их сравнение в P3-12 содержательно.
5. Каждый описывает хотя бы один блок Use Cases: x_i,P3-02 + x_i,P3-03 + x_i,P3-04 ≥ 1. Все участники должны знать сценарии, которые затем оценивают в коллективной экспертизе.

Это задача целочисленного линейного программирования (обобщённая задача о назначениях с дополнительными ограничениями). Модель в формате CPLEX LP: [модель распределения.lp](<Расчёты/модель распределения.lp>) — её можно загрузить в GLPK, NEOS или OpenSolver.

## Решение

**Инструмент** — GLPK (библиотека glpk.js, метод ветвей и границ) в скрипте [phase2.mjs](<Расчёты/phase2.mjs>). Для контроля скрипт перебирает все 3¹² = 531 441 назначение: допустимых 534, максимум целевой функции совпадает с решением GLPK.

| Участник | Задачи | Нагрузка, ч |
|---|---|---|
| E1 Виктор Фазятденов | P3-02 (UC-01–UC-05), P3-06 и P3-07 (COSMIC) | 15 |
| E2 Виктор Мазниченко | P3-04 (UC-11–UC-14), P3-05 (диаграмма и каталог UC), P3-12 (выводы), P3-13 (отчёт) | 14 |
| E3 Даниил Ситков | P3-03 (UC-06–UC-10), P3-08 и P3-09 (UCP), P3-10 и P3-11 (экспертная оценка) | 17 |

Целевая функция — 217 из 222 возможных: столько было бы, если бы каждая задача досталась тому, кто хочет её больше всех, без ограничений. Потеря 5 единиц — цена баланса: блок UC-01–UC-05 больше всех хочет E3 (5 против 4 у E1), но с ним нагрузка E3 вышла бы за 17,63 ч. Поэтому блок получил E1. Средневзвешенное предпочтение по назначенным задачам: E1 — 4,67, E2 — 4,57, E3 — 4,88.

Оптимальных назначений два, с одинаковым значением 217. Команда приняла решение GLPK; второе отличается перестановкой задач с равными произведениями p · c и на нагрузку существенно не влияет.
